## Search

```sh
jira search 'project = ABC AND created >= -7d' --json | jq -r '.[].key'
jira count 'project = ABC AND status = Done'
```

`search <jql>` takes `-n, --limit <n>` (default 50) and `--json`. See [Setup](/projects/jira-cli/docs/setup) for the truncation exit code. `count` prints the number of matches.

## People

```sh
jira whoami
jira whoami --permissions --project ABC   # global admin and project admin
jira user search ada --project ABC
```

`user search <query>` takes `-p, --project <key>` to restrict to users assignable on that project, and `-n, --limit <n>` (default 20).

## Saved filters

```sh
jira meta filters                                   # every filter you can see
jira filter view 10200                              # JQL, owner, shares with their IDs
jira filter create --name 'Open bugs' --jql 'type = Bug AND resolution IS EMPTY'
jira filter edit 10200 --jql 'type = Bug ORDER BY priority DESC'
jira filter share 10200 --project ABC               # or --project ABC --role Developers
jira filter share 10200 --group shop-leads          # or --user <account id or email>
jira filter share 10200 --logged-in                 # or --public, where the site allows it
jira filter unshare 10200 7                         # share ID from filter view
jira filter delete 10200 --yes
```

A new filter is private until shared. `share` adds one view share per call: exactly one of `--project` (with an optional `--role`), `--group`, `--user`, `--logged-in` or `--public`. It needs the global *Share dashboards and filters* permission, and a refusal says so. `edit` and `delete` work only for the owner, someone the filter is shared with for editing, or a Jira admin; when Jira refuses, the error names the owner. `delete` asks first, and needs `--yes` when stdin is not a terminal. `view`, `create`, `edit` and `share` take `--json`.

## Instance metadata

`jira meta` shows what your Jira supports, useful for getting names right before creating things:

```sh
jira meta issuetypes      # also: priorities, statuses, resolutions, linktypes
jira meta labels
jira meta filters
jira meta permissions ABC
jira meta server
```

## Escape hatch

Anything not covered goes through `jira api`:

```sh
jira api /rest/api/3/myself
jira api /rest/api/3/issue/ABC-123/watchers -X POST -d '{"accountId":"..."}'
```

`-X, --method` defaults to `GET`, and `-d, --data` takes a JSON body. A 2xx response with an empty body prints nothing and exits 0, so `null` only ever means Jira really answered null. A non-2xx response is an error and shows the body.

## Scripting

Every read command takes `--json`, and colour is off when stdout is not a TTY or `NO_COLOR` is set:

```sh
jira issue list --mine --json | jq -r '.[].key'
```
